# WinPE UEFI-PXE fixture artifacts — provenance (Issue #71)

The `scripts/bve-winpe-pxe-proof.sh` host proof needs five boot-critical files
staged into `$BAMEP_BVE_WINPE_FIXTURE_ROOT`. They are **not** committed
(third-party / Microsoft-redistribution-restricted binaries — the same policy as
`integration/physical/issue-53-winpe-secure-boot/.gitignore` and ADR-0021).
Their SHA-256 and expected sizes are pinned in
`scripts/winpe-pxe-fixture.sha256`; a mismatch or a missing file is an
actionable prerequisite error — the harness never downloads a replacement and
never falls back to a different artifact.

These are the exact artifacts qualified in the Issue #53 physical Secure-Boot /
WinPE chain (`docs/reference/physical-secure-boot-winpe-network-delivery.md`),
**minus** the Secure-Boot wrapper — Issue #71 uses non-Secure-Boot OVMF and
non-Secure-Boot iPXE, so no `shim` / `snponly-shim.efi`.

| File | Size (bytes) | Source |
| --- | ---: | --- |
| `snponly.efi` | 287 232 | `ipxeboot/x86_64/snponly.efi` from the official iPXE **v2.0.0** release bundle (`ipxeboot-v2.0.0.tar.gz`). The **non**-Secure-Boot SNP-only build. |
| `wimboot` | 76 064 | Official `wimboot` **v2.9.0** release binary. |
| `BCD` | 262 144 | `Boot\BCD` from a retained Windows ADK **WinPE 10.0.26100** media tree (`copype amd64`). Pristine — not the PXE-authored BCD. |
| `boot.sdi` | 3 170 304 | `Boot\boot.sdi` from the **same** ADK WinPE media tree. |
| `boot.wim` | 340 134 390 | `sources\boot.wim` from the **same** ADK WinPE media tree — stock, DISM-reported version `10.0.26100`, edition `WindowsPE`, x64. No customization, no driver injection. |

The `BCD` + `boot.sdi` + `boot.wim` set must come from one mutually compatible
ADK WinPE media lineage (ADR-0021): `wimboot` alone extracting BCD/boot.sdi from
`boot.wim` did not suffice in the tested deployment image.

`boot.ipxe` is generated by the harness (`bamep_ve::winpe_boot_ipxe_script`) —
do not stage it.
